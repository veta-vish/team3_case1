# 5 тест-сценариев

## T1-1. Успешная оплата (ОБРАЗЕЦ)

**Вход:**
Создание платежа по данным из `payments.csv`: `order\\\_id = ord\\\_1001`, `amount = 2500.00`, `currency = RUB`, `recipient = clinic\\\_medservice`.

**Ожидание:**

* Платёж создан, статус `SUCCESS`.
* В `payments\\\_out.csv` появилась запись.
* `error\\\_code` отсутствует.

**Факт:** Скрипт вернул статус SUCCESS, запись создана.  
**Пройден:** \[x] да \[ ] нет

## T1-3. Неверные данные (Валидация)

**Вход:**
Платёж с неверной валютой: currency = USD (нарушено правило V-4).

**Ожидание:**

* Платёж отклонен (HTTP 422).
* `error\\\_code` соответствует нарушенному правилу (`UNSUPPORTED\\\_CURRENCY`).

**Факт:** Скрипт вернул VALIDATION_ERROR с кодом UNSUPPORTED_CURRENCY. Запись в CSV не добавлена.
**Пройден:** \[x] да \[ ] нет

\---

## T1-4. Повтор запроса (Идемпотентность)

**Вход:**
Два запроса на создание/подтверждение платежа с одинаковым `Idempotency-Key` (`idem\\\_0001`) и одинаковым `order\\\_id`.

**Ожидание:**

* Второй запрос не создает дубликат.
* Возвращается тот же `payment\\\_id` и статус, что и в первый раз (HTTP 200).
* В БД (в `payments\\\_out.csv`) только **одна** запись.

**Факт:**  Второй запрос вернул тот же ответ, но с флагом "idempotent_replay": true. Дубликат в CSV не создан.  
**Пройден:** \[x] да \[ ] нет

\---

## T1-5. Таймаут эмулятора

**Вход:**
Платёж с `order\\\_id = ord_2016`, для которого эмулятор шлюза (по хэшу) возвращает `TIMEOUT`.

**Ожидание:**

* Клиенту возвращается статус `PENDING` (платеж в обработке).
* В логах зафиксирован `TIMEOUT`.
* Повторный запрос с тем же `Idempotency-Key` безопасен.

**Факт:** Скрипт вернул статус PENDING и `error\\\_code = TIMEOUT`. В CSV добавлена запись.
**Пройден:** \[x] да \[ ] нет
